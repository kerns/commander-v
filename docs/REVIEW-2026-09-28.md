# Commander V assessment — 28 September 2026

## Assessment

Commander V has a small, useful core: resolve a selection, collect text, describe its structure, format a payload, and copy it. The 2.4.7 implementation was understandable, but lacked a reliable development/release loop and repeated expensive work. The highest-value first step was to establish tests and correct that pipeline. It does not need a framework, bundler, or TypeScript rewrite to remain maintainable.

This pass produced **Commander V 3.0**, package version **3.0.0**. Intermediate 2.5.0 and 2.6.0 test builds were not published. Existing README edits, the prior removal of redundant activation events, and the user's untracked `src/My Project/` sample have been preserved. See the [release record](RELEASE-3.0.md) for publication and final acceptance results.

## Findings addressed

| Priority | Original finding | Change |
| --- | --- | --- |
| High | A folder's contents were read during classification, again during ordering, and again for output. | One deduplicating traversal; read each file once and retain its text. |
| High | `directory-tree` synchronously scanned before ignored nodes were filtered; even pruned trees walked unrelated paths. | Build pruned trees directly from selected paths. Full trees use async provider reads, depth limits, and exclusion before descent. |
| High | Dependency and tooling maintenance had fallen behind. | Removed legacy dependency chains, updated tooling, and generated a tracked lockfile. Current audit reports zero known vulnerabilities. This is a package audit result, not a claim that all possible security issues have been ruled out. |
| High | No functional tests; `npm test` deliberately failed; the packaging command relied on a missing global `vsce`; lockfile ignored by Git. | Unit and real-host integration tests, local packager, repeatable install scripts, CI matrix, Dependabot, tracked lockfile. |
| Medium | `workspaceFolders[0]` failed without a folder and attributed all selections to the first root. | Resolve actual workspace folders, support loose files, qualify multi-root labels. |
| Medium | `Uint8Array.toString()` could output comma-separated byte values instead of UTF-8 text. | Decode via `Buffer.from(bytes).toString('utf8')`. |
| Medium | Unsaved text was read only from visible editors, ignoring open background tabs. | Index `workspace.textDocuments`. |
| Medium | Errors during configuration and discovery escaped the command's catch block; binary-only selections could overwrite the clipboard. | Catch the entire operation; do not write for empty, failed, or cancelled selections. Save previous selection only after successful output. |
| Medium | Ignore lines were treated as escaped regex substrings; globs, negations, anchoring, and directory semantics did not work. | Use `ignore` for the configured root ignore file. |
| Medium | Folder copies could include dependency installations and generated artifacts; tree exclusions depended entirely on a project file. | Shared, overridable defaults for modern web and Python projects; project rules extend them, and explicit individual files can still be copied. Excluded directories are skipped before descent. |
| Medium | Executable local config had no explicit trust gate, was cached indefinitely, and swallowed actual load errors. | Explicit limited Restricted Mode support; execute only when trusted; reload and validate settings; surface load errors. The original extension was disabled by default in Restricted Mode, so this was a missing explicit contract, not a demonstrated default trust bypass. |
| Medium | File ordering differed from the directory-first tree; path substring checks could collide. | Shared deterministic directory-first ordering and segment-aware relative paths. |
| Medium | Sound asset path pointed outside the extension, eagerly probing for players on activation. Success notification passed an unsupported Markdown object. | Lazy optional system audio using the correct asset path and bounded execution; real action button opens extension management. |
| Low | A triple-backtick wrapper could be terminated by Markdown in the selected files; dollar signs in filenames could be substituted unexpectedly. | Choose a long enough fence and replace filename placeholders literally. |
| Low | Broad packaging exclusions could accidentally ship scratch files and old builds. | VSIX allowlist includes runtime code, metadata, required assets, and the sole runtime dependency. |
| Low | Cancellable progress flashed briefly even for a few files, followed immediately by a completion notification. | Start copying immediately and reveal progress only after one second if still running. Close progress before requesting the completion message; keep cancellation available for longer copies. |

## Dependencies and compatibility

Runtime dependency: `ignore` 7.0.10. Development dependencies: `@vscode/test-electron` 3.1.0, `@vscode/vsce` 4.0.0, ESLint 10.11.0. These are the npm latest versions checked during this pass; `npm outdated` returned no entries. Removed unused Node type definitions rather than upgrading declarations that plain JavaScript did not consume. Removed `@agarimo/archy`, `directory-tree`, and `play-sound`.

`npm outdated --all` still lists 69 distinct installed transitive package names below their registry latest releases, all in development tooling and all at their parents' wanted versions after `npm update`. They are excluded from the VSIX. These upstream constraints remain; the claim is current direct dependencies and zero known audit findings, not literally zero older versions anywhere. See the [full dependency inventory](DEPENDENCIES-2026-09-28.md). A clean `npm ci` succeeded.

GitHub Actions were checked against their official latest release pages: checkout 7.0.1, setup-node 7.0.0, upload-artifact 7.0.1. Weekly updates are configured. Development uses Node 24 LTS; the supported editor floor is VS Code 1.105.0 (September 2025), explicitly tested instead of leaving an unverified 2023 compatibility claim. This raises the minimum version and should be called out in a public release.

The extension retains its identity (`kerns.commander-v`), existing command IDs, keyboard bindings, and settings. Notable behavior corrections: directories precede sibling files, symlinks are skipped during content collection, local config reloads, invalid config fails clearly, and empty selections preserve the clipboard. Linux audio uses `paplay`; remote audio is disabled. Version 3.0 adds a tree-only command and shortcut, uses conventional four-column tree branches, and wraps trees in unlabeled Markdown code blocks by default. ASCII branches and raw tree text are configurable. Both copy modes delay cancellable progress by one second; fast copies show just their success notification and optional sound.

## Performance evidence

A local macOS arm64 run over 1,000 small text files produced:

| Operation | File reads | Directory reads | Illustrative elapsed time |
| --- | ---: | ---: | ---: |
| Original selection pipeline | 3,000 | 2 | 241 ms |
| New selection pipeline | 1,000 | 1 | 87 ms |
| New pruned tree | 0 | 0 | 6 ms |

This is an I/O comparison with local filesystem adapters, not an end-to-end editor benchmark. Cache order, hardware, file sizes, and provider latency affect elapsed time; do not advertise a universal 3× speedup. The read-count reduction and absence of pruned-tree scans are asserted by tests. For remote projects, bounded parallel reads could provide another improvement, but should be measured on a real remote host before selecting a concurrency limit.

## Validation completed locally

- Lint and 61 unit regression tests passed for 3.0.0. Delayed-progress checks cover fast and slow copies, the one-second boundary, cancellation before clipboard work, notification failures, and cleanup after task errors. Release CI also caught and verified corrections for Windows drive-letter casing and the versioned Windows CLI layout.
- All 32 real-host integration checks passed using the final installed 3.0.0 VSIX on VS Code 1.105.0, installed VS Code 1.135.0, and current stable 1.139.1 on macOS arm64. They include native progress lifecycle checks, tree-only behavior, shared exclusions and opt-out, explicit-file overrides, per-folder settings, local config reload/error recovery, formatting controls, and the Manage Extension action.
- Replaced a cached minimum-version editor that had updated itself to 1.139.1 with a fresh official 1.105.0 download, then reran the suite successfully on Node 22.19.0. The harness now disables editor updates and asserts explicitly requested host versions so a changed cache cannot produce a misleading compatibility result.
- Installed 3.0.0 in the normal VS Code profile, verified installed runtime files match the packaged source, and ran **Developer: Reload Window**. A quick command-palette copy of the open demo file completed with the success notification (1 file, 4,158 characters); no progress notification remained. Existing unsaved documents were preserved.
- Tree fences omit the optional `text` language label, following the user's Codex/Claude paste tests. The backticks, indentation, and adaptive fence length remain intact.
- A final hands-on acceptance pass exercised the packaged extension in an isolated VS Code 1.139.1 profile: all three Mac shortcuts, multiple-file and folder context actions, files-only copying, raw ASCII trees, unsaved background tabs, and the Manage Extension button. Native Cancel buttons stopped both tree traversal and file collection while preserving a clipboard marker. A concurrent command was held off, and reuse worked after cancellation.
- A complete 50,000-file run copied every file exactly once with a pruned tree: 9,751,928 characters / 10,650,334 UTF-8 bytes. This demonstrates a large local case, not unlimited capacity or cancellation within synchronous formatting.
- Verified activation, exact tree/text output, deduplication, reuse, multi-root selections, unsaved background editors, saved-file mode, command-palette use, binary/empty selections, removed files, ignore globs, formatting options, loose files, and error clipboard preservation.
- Tree-only checks cover no reads of listed file bodies, binary filenames, empty folders, depth limits, workspace-relative ignore patterns, overlapping roots, previous-selection preservation, Unicode/ASCII rendering, and Markdown fences. Shortcut scope defaults to the active workspace; folder context actions copy the selected subtree. Nested symlinks are listed without following them.
- Inspected VSIX contents: 24 files, approximately 2.16 MB compressed, including delayed-progress handling and the shared default ignore rules; only `ignore` ships as a runtime dependency.
- All six [cross-platform CI jobs](https://github.com/kerns/commander-v/actions/runs/36451003312) passed: 61 unit tests and 32 installed-VSIX integration checks per job, covering VS Code 1.105.0 and 1.139.1 on Windows, macOS, and Linux. Real SSH/container behavior and Windows/Linux audio remain unverified.

## Organization

- `extension.js`: command lifecycle, progress, clipboard writes, previous selection, and error reporting.
- `src/files.js`: traversal, de-duplication, decoding, ordering, and workspace grouping.
- `src/projectTree.js`: tree construction, ignore matching, and rendering.
- `src/treeOnly.js`: tree-only root selection and directory collection without file-content reads.
- `src/exclusions.js` and `src/default.ignore`: shared project/default exclusion rules, with user overrides.
- `src/configuration.js`: scoped settings, trusted local overrides, and validation.
- `src/format.js`: pure output formatting.
- `src/notifications.js`: user notification and optional audio.
- `src/progress.js`: delayed progress display, cancellation forwarding, and notification cleanup.

Tests inject a filesystem/VS Code adapter into the I/O code. Integration tests exercise registered commands in the real host, including an installed VSIX using an independent harness. Keep this separation as changes are made; avoid growing a miscellaneous `utils.js` again.

## Follow-up work and validation limits

1. **Medium: extend ignore discovery if needed.** The user approved shared defaults for folder contents and trees, with explicit-file overrides. This is implemented and documented in [the exclusion policy](EXCLUSIONS.md). Nested `.gitignore` files and global Git ignores are not currently loaded; custom framework output and virtual-environment locations still need project rules. These are path filters, not content inspection.
2. **High: bound very large selections.** Content and the final clipboard string remain in memory. A 50,000-file / 10.65 MB output case passed locally, but this is not a bound on memory usage. Cancellation works between I/O operations, but cannot interrupt one large provider read or synchronous formatting. Decide per-file/total-byte limits and the user-facing handling of oversized files, then add larger/adversarial stress tests.
3. **Medium: strengthen encoding detection.** The inherited NUL-byte heuristic excludes UTF-16 and misses some binary formats with no NUL bytes. Define supported encodings and binary detection before adding another library.
4. **Medium: test remote environments and remaining desktop interactions.** URI handling has adapter coverage, and Windows/Linux/macOS CI passes. Actual SSH/Codespaces behavior, Windows/Linux keyboard interactions, and audio still need verification in those environments.
5. **Medium: multi-root configuration policy.** Formatting comes from the first selected item's folder. Duplicate workspace folder names can create ambiguous labels. Establish whether per-root settings should apply to content or whether the selection should use one explicit preset.
6. **Low: asset size.** The PNG icon is about 1.84 MB and the WAV about 691 KB. Most of the roughly 2.15 MB compressed VSIX is media. Export a smaller icon and audio asset before considering a bundler; runtime code is already small. The assets were preserved in this pass.
7. **Low: broader settings/UX audit.** Review existing broad shortcut bindings, output character counts versus byte/token estimates, and whether previous selections should persist across reloads. These are product decisions and are deferred with new feature work.

The next iteration should focus on the first two items and cross-platform validation, followed by hands-on feedback on the local candidate. Feature ideation can follow once that baseline feels reliable.
